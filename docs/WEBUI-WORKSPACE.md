# Memex Workspace: integrated local Web UI

이 UI는 0.4.2 / `f2dfc02967c35c5c9b64090e904779dcfe5cafb9`의 읽기 스키마·팩트 관리 서비스·CLI를 설계 기준선으로 삼아 구성됐고, 0.5.0과 함께 배포되며 0.5.0 릴리스 게이트에서 현재 스키마로 검증됐다. 기존 `ui/server.cjs` bin과 `ui/` 패키징을 유지한다.

## 화면

`/` 개요, `/conversations` 대화 원장, `/facts` 기억·사실, `/taxonomy` 분류, `/graph` WebGL/Canvas 지도, `/activity` Chronicle·작업·모델 시도·주입·로그·관리 실행, `/settings` 런타임·관리 작업·동기화·화면 설정·진단.

범위는 상단에서 명시적으로 선택하며 선택 순서는 **전체 프로젝트 (조회) → 공통 기억 → 프로젝트 목록**이고, 각 항목에 그 범위의 활성 기억 수를 함께 보여준다. 화면의 기본값은 **전체 프로젝트 (조회)** 다(0.6.1, #24). 프로젝트 범위는 공통 기억 포함 여부와 승격 상태(`promotion_state`)를 구분한다. 상세 패널과 검색에도 같은 범위를 적용한다.

전체 프로젝트는 **조회 전용 범위**이고 실제 주입 범위와 다르다. 그래서 범위 선택 옆에 `주입: 현재 프로젝트 + 공통 기억` 안내를 상시 표시한다. 대화 원장·활동·개요는 공통 기억 범위에서 항상 0건이므로(대화와 작업은 프로젝트 세션에 묶여 있다) 배너에서 한 번의 클릭으로 전체 프로젝트로 전환한다.

`/facts?fact=<id>`는 `/facts/<id>`와 같은 상세 패널을 연다(#26).

본문은 14px, **보조 텍스트도 11px 아래로 내려가지 않는다**(#26). 밀도 설정은 글자 크기가 아니라
표·타임라인의 세로 여백을 조절한다.

**0.6.0 기억 계층과의 대응.** 화면에 보이는 승격 상태는 [범위 모델](FACT-LIFECYCLE.md#1-fact란-무엇인가)의
세 계층과 다음처럼 대응한다: `workstream`(과 `workspace`) = 브랜치 tier, `project-current`(와 `decision`) =
프로젝트 공용, `scope_type = global` = 글로벌. 새 기억의 기본 계층은 세션의 브랜치 신호가 정하므로,
기본 브랜치나 비-git 디렉터리에서 만들어진 기억은 프로젝트 범위 화면에 바로 나타난다.
`facts.tier_reason`이 그 근거를 담는다.

### 계층 배지와 숨겨진 계층 (0.6.1 #22)

기억 행과 상세 패널 요약 탭에 **주입 계층** 배지를 단다. 라벨은 `글로벌 공용` / `프로젝트 공용` /
`브랜치: <name>` / `워크스페이스` 네 가지이고, 툴팁 한 문장이 그 계층의 주입 조건을 말한다. 브랜치
이름은 `facts.tier_reason`의 `branch:<name>`이 우선이고 없으면 작업 흐름의 `branch_hint`를 쓴다.
둘 다 없으면 이름을 지어내지 않고 `브랜치`로만 표시한다.

`/api/v2/facts`는 같은 프로젝트에 있지만 현재 술어 밖인 기억 수를
`hiddenByTier: {workstream, workspace}`로 함께 돌려준다. 0이 아니면 기억·사실 화면과 개요에
"브랜치/작업 흐름 범위 기억 N건이 더 있습니다 → 포함해서 보기" 배너가 뜨고, 토글은 쿼리 파라미터
`tiers=all`을 켠다. 이 상태는 상단 **상세 조회 범위** 모달의 체크박스와 같은 값을 공유한다.
`tiers=all`은 계층 술어만 풀 뿐 프로젝트 경계는 넓히지 않는다. `hiddenByTier`는 `tiers=all` 상태에서도
기본 술어 기준으로 계속 보고하므로 토글을 되돌릴 수 있다.

상세 패널 › 처리·재사용의 **"이 기억이 주입되는 조건"** 절이 계층·프로젝트·브랜치·활성 여부와
마지막으로 실제 제공된 recall 기록을 함께 보여준다. 조건을 만족해도 관련성 게이트에서 탈락할 수
있다는 사실을 같이 적는다.

### 승격/강등과 계층 이관 (0.6.1 #22)

상세 패널의 **계층 승격 / 계층 강등** 버튼이 `/api/v2/facts/promote|demote`(POST, CSRF, 감사 1줄)를
통해 `dist/fact-management.js`의 `promoteFact`/`demoteFact`를 `actor: 'user'`로 호출한다. 사다리는
`브랜치 ⇄ 프로젝트 공용 ⇄ 글로벌`이고 **한 번에 한 칸만** 움직인다 — 글로벌로 보내려면 먼저
프로젝트 공용으로 승격해야 하며, 사다리 끝 방향의 버튼은 미리 비활성화한다. 결과는 Chronicle
`PROMOTED`/`DEMOTED` 이벤트로 남아 변경 이력 탭에 즉시 나타난다. UI는 `user-directive`를 쓰지 않는다.

0.6.2(#77)부터 더블클릭 같은 **중복 요청이 두 칸을 움직이지 못한다**. 서버는 (1) per-id 잠금을 첫
`await`보다 **먼저** 잡고(두 번째 요청 → 409 `MUTATION_BUSY`), (2) 코어에 사용자가 승인한 **한 칸**을
`options.to`로 명시하고 읽어온 tier·행 버전을 `options.expected = { tier, updatedAt }`로 함께 넘긴다.
경쟁에서 진 요청은 코어의 `TierStaleError`(→ 409 `STALE_FACT`) 또는 `TierStepError`(→ 409 `TIER_STEP`)로
거절되며 아무것도 기록되지 않는다. 사다리 끝 방향의 요청은 쓰기를 열기 전에 409 `TIER_STEP`이 된다.

관리 › 관리 작업의 **기억 계층 이관** 카드는 `memex facts migrate-tiers --dry-run` 출력을 그대로
보여주고, 미리보기를 실행한 뒤에만 `--apply` 버튼이 열린다. 두 실행 모두 기존 관리 명령 경로
(`lib/operations.cjs` allowlist · 확인 모달 · 감사 로그)를 그대로 쓴다.

## 동기화 탭 (0.6.1 · 0.6.3 #48)

관리 › **동기화**는 `dist/sync-control.js`의 `getSyncStatus` · `setSyncEnabled` · `runSyncExport` ·
`runSyncImport` · `exportGenerationArchive` · `previewImportArchive` · `importArchive` ·
`setDeviceAlias`를 **엔드포인트 하나**(`/api/v2/sync`)로 노출한다. GET은 조회, POST는 본문의
`action`으로 동작을 고르며 CSRF·명시적 확인(`confirm: true`)·감사 1줄을 요구한다. 하위 경로
(`/api/v2/sync/...`)는 없다.

| `action` | 무엇을 하나 | 추가 본문 |
| --- | --- | --- |
| `enable` / `disable` | 스위치와 공유 폴더 지정 | `dir`(절대 경로) |
| `export` / `import` | 공유 폴더로 지금 내보내기 / 가져오기 | — |
| `archive-export` | 새 세대를 만들고 zip으로 저장(동기화가 꺼져 있어도 동작) | — |
| `archive-preview` | 세대 파일 검증 + 적용 미리보기(**아무것도 바꾸지 않음**) | `path` |
| `archive-import` | 검증한 세대 파일 적용 | `path` |
| `alias` | 기기 이름 지정·삭제 | `deviceId`, `alias`(빈 값이면 삭제) |

- **스위치는 기본 꺼짐**이다. 켜는 모달에서 공유 폴더 절대 경로를 받아 폴더를 만들고 **지금 쓰기
  가능한지 확인**한다. 실패하면 켜지 않는다. 설정은 데이터 루트의 `sync/config.json`에 저장된다.
- 상태 블록은 공유 폴더와 그 **경로 출처**(`MEMEX_SYNC_DIR` 환경 변수 / 이 화면에서 지정 / 기본 로컬
  경로), 접근·쓰기 가능 여부, 설정 파일, 이 기기 ID(첫 내보내기에서 부여), 마지막 내보내기의 세대
  시각·행 수·오류, 그리고 감지된 다른 기기의 세대·시각·행 수를 보여준다. manifest를 읽지 못한
  기기의 행 수는 0이 아니라 "읽지 못했습니다"로 표시한다.
- **지금 내보내기 / 지금 가져오기**는 확인 모달을 거치고 모델을 호출하지 않는다. 꺼져 있으면
  비활성화하고 그 이유를 적는다. 사용자가 직접 누른 내보내기는 변경이 없어도 세대를 만든다
  (`force`); 자동 훅만 빈 세대를 피한다.
- 가져오기 결과(`+N / ~N / -N`)와 **거부된 세대의 사유**는 코어가 돌려준 `malformedRows`를 그대로
  보여준다. 세대는 하나라도 깨지면 통째로 거부된다. 이 결과는 서버가 실행되는 동안만 화면에 남는다.
- 코어 모듈은 자기 경로를 `MEMEX_HOME` / `MEMEX_DB_PATH`에서 읽으므로, 호출 동안 이 서버가 해석한
  home·DB로 환경을 고정했다가 되돌린다(`lib/core.cjs` `pinned()`). 임시 DB를 가리킨 세션이 실제
  데이터 루트에 쓰지 않게 하는 장치이고, 그 창이 겹치지 않도록 동기화 호출은 한 번에 하나만 실행한다.
  0.6.2(#76)부터 그 잠금은 **첫 `await`보다 먼저** 잡히고 환경 저장·복원도 같은 블록 안에 있다.
  검사와 설정 사이에 양보 지점이 없으므로 두 번째 요청은 409 `SYNC_BUSY`로 거절되고, 저장해 둔
  값은 항상 호출 전 원본이다(원래 정의되지 않았던 변수는 호출 뒤에도 정의되지 않는다).

### 코어 호출의 경로 고정 (0.6.3 #78)

`pinned()`는 동기화 전용이 아니다. **계층 승격·강등과 기억 변경(수정·비활성화·복원·영구 삭제)도
같은 헬퍼를 통과한다.** 코어는 `actor: 'user'` 변경마다 `logs/ui-audit.jsonl`에 한 줄을 남기고 그
경로를 `getMemexHome()`으로 정하므로(`src/paths.ts`), 고정하지 않으면 그 줄이 **UI의 home이 아니라
기본 데이터 루트**(`XDG_CONFIG_HOME/memex` 또는 `~/.config/memex`)로 갔다 — `MEMEX_DB_PATH`로 임시
DB를 가리킨 UI가 사용자의 실제 데이터 루트에 기록을 남기고, 감사 줄이 두 루트로 쪼개졌다. 이제 UI
자신의 감사 줄(`lib/logs.cjs`)과 코어의 감사 줄이 항상 같은 home에 있다. 기록은 fact id와 project
id뿐이며 경로나 기억 본문은 들어가지 않는다.

### 수동 파일로 주고받기 (0.6.3 #48)

공유 폴더를 쓸 수 없는 기기를 위한 두 번째 경로다. **형식을 새로 만들지 않는다**: zip 하나에
committed generation의 다섯 파일(`meta.json` + 4개 JSONL)이 그대로 들어가므로, 가져오기는 공유
폴더와 **똑같은 protocol v5 검증**(manifest 일치 · 행 수 · SHA-256 · 행 스키마 · 안정 식별자)을 통과한다.

- **내보내기**는 새 세대를 만든 뒤 그 세대를 zip으로 **데이터 루트 안**
  (`<data root>/sync/exports/<device>-<generation>.zip`)에 쓰고 경로·크기·행 수를 보여준다.
  브라우저 다운로드는 이 UI에서 쓰지 않으므로(loopback + CSP) 경로 복사와 Finder `⇧⌘G` 안내로
  대신한다. 서버가 쓰는 경로는 **데이터 루트 밖으로 나갈 수 없다** — 오타나 악성 페이지가 임의
  파일을 덮어쓰지 못하게 하는 경계다. 0.6.6(#101)부터 그 판정은 문자열 접두사가 아니라 **실제
  위치**다: 존재하는 가장 깊은 조상을 `realpath`로 해석하고, 마지막 구성요소가 심볼릭 링크면
  따라가지 않고 거부하며, 기본 경로도 같은 검사를 받는다.
- 이 내보내기는 **공유 폴더를 쓰지도, 만들지도 않는다**(0.6.6 #95). 세대는 데이터 루트 안의 전용
  staging에서 만들어 zip으로 묶고 staging은 지워지므로, 동기화가 꺼져 있거나 공유 폴더를 지워 둔
  상태에서 눌러도 폴더가 되살아나지 않고 다른 기기가 가져갈 세대도 생기지 않는다. 그래서
  `export-status.json`을 건드리지 않는 설계가 일관된다 — 그 기록은 *공유 폴더*에 무엇이 도달했는지에
  대한 진술이고, 여기서는 아무것도 도달하지 않는다.
- **가져오기**는 항상 **검증 → 미리보기 → 확인** 순서다. 미리보기는 보낸 기기·세대, 적용 시
  `+N / ~N / -N`, 충돌 목록, 거부된 세대의 사유를 보여주고 **아무것도 바꾸지 않는다**(계획 계산은
  롤백하는 트랜잭션 안에서 돌린다). 0.6.6(#97)부터는 DB를 **만들지도 마이그레이션하지도 않는다**:
  로컬 인덱스가 없으면 `no local index yet …` 사유로 거부하므로, 인덱스가 없는 기기에서는 먼저
  `memex sync`를 한 번 돌려야 미리보기가 가능하다(적용은 전과 같다). 미리보기는 같이 들어오는
  삭제 표식을 **먼저 반영한 뒤** fact를 계획하므로 적용과 같은 숫자를 말한다(0.6.6 #103).
  미리보기의 `~N`은 **기억 개수**이고 적용 결과의 `~N`은 의미·근거·활성 상태를 축별로 세므로 더 클
  수 있다 — 화면에 그 차이를 적는다.
- 거부 사유는 코어 원문 그대로 싣는다. 이 기기가 만든 파일, zip이 아닌 파일, 세대 파일이 아닌
  zip은 각각 다른 문장으로 거부된다(실패 클래스 `sync-archive-invalid`).

### 기기 이름 (0.6.3 #48)

`device_id`는 UUID라 화면에서 읽을 수 없다. 별칭은 데이터 루트의 `sync/devices.json`(스위치 옆,
**공유 폴더가 아니다**)에 저장하고, 상태 블록과 다른 기기 표에서 바로 편집한다.

- **이 기기의 이름만** 세대 `meta.json`의 `device_alias`로 실려 다른 맥에도 보인다(추가 필드이므로
  구버전 피어는 무시한다). 0.6.6(#98)부터 이 이름은 내보내기 게이트의 fingerprint에 들어가므로,
  이름을 바꾸거나 지우면 **다음 자동 내보내기**가 새 세대를 게시해 상대에게 전달한다. 다른 기기에
  붙인 로컬 이름은 manifest에 실리지 않으므로 내보내기를 일으키지 않는다.
- 다른 기기에 붙인 이름은 **이 기기에만** 남고 상대의 설정을 바꾸지 않는다. 로컬 이름이 상대가
  보낸 이름을 이기므로, 상대의 다음 export가 내 이름을 되돌리지 않는다. 표는 상대가 보낸 이름임을
  따로 밝힌다.
- 기기 ID는 첫 내보내기에서 부여되므로 그 전에는 이름 지정 버튼이 잠긴다.

### 충돌 이력 (0.6.3 #48)

가져오기에서 **같은 기억의 의미가 달랐을 때만** Chronicle `SYNC_IMPORTED` 이벤트가 남는다(새 기억
추가나 같은 문장은 충돌이 아니다). `actor: 'sync'`, `projection_applied = 0`, `effective_at`은 피어의
의미 수정 시각이고, `outcome`에 `source_device_id` · `source_device_alias` · `generation` ·
`winner`(`peer`/`local`) · `reason`이 들어간다.

- 활동·추적 › **지식 변경** 타임라인과 **기억 상세 › 변경 이력**에 `기기 <이름>에서 가져옴` 라벨과
  누가 남았는지(`가져온 값으로 대체됨` / `이 기기의 값이 남음`)가 붙는다. 충돌 이벤트에서는
  이전/이후 대신 **밀린 값 / 남은 값**으로 적는다.
- 이벤트 상세는 가져온 기기·세대와 판정 근거(더 최근 시각 / 동시각 결정 규칙)를 보여준다.
- 이 이벤트는 **내보내지 않는다**(`src/sync-export.ts` `LOCAL_ONLY_EVENT_KIND`). 이 기기가 내린
  판정이지 공유할 진실이 아니고, 내보내면 상대 기기가 자기 때문에 생긴 기록을 되받는다. 덕분에
  0.6.2 피어는 이 kind를 볼 일이 없어 프로토콜 변경이 아니다.

**아직 검증되지 않은 것**: 실제 두 대의 맥 사이 라운드트립(`liveTwoDeviceRoundTrip: NOT_PROVEN`).
기능은 모두 들어와 있고 temp 데이터 루트 두 개로 자동 검증하지만, 실제 기기 두 대에서의 확인은
사용자 테스트로 남아 있다.

## 도움말과 용어집

`public/help.mjs`는 문서 없이 화면만 보고도 용어와 기능을 이해할 수 있게 하는 카탈로그다(0.6.1 #28).
정의의 단일 출처는 `docs/GUIDE.md`와 이 문서이고, 항목마다 `source`로 그 앵커를 가리킨다.

- 페이지 제목 옆 **ⓘ**: 한 문단 설명과, 릴리스 태그에 고정된 GitHub 문서 링크. 로컬 파일 경로를
  내보내지 않는다(코어 버전을 모르면 `main`으로 떨어진다).
- 상단 컨트롤 · 상태 배지 **전종** · 표 머리글 · 관리 명령에 한 줄 `title` 툴팁. 키보드 포커스에서도
  뜨는 네이티브 툴팁이라 별도 컴포넌트를 만들지 않는다.
- **용어집**: `?` 단축키 또는 사이드바 아래 링크. 검색 가능하며 각 항목이 해당 화면과 문서로 이어진다.
- 관리 › 화면 설정의 **도움말 표시: 항상 / 처음만 / 끄기**. "처음만"은 한 번 연 항목을 이 브라우저에
  기록해 다시 띄우지 않고, "끄기"는 ⓘ와 용어집 링크를 감춘다. 한 줄 툴팁은 항상 남는다.
- 첫 실행 투어는 넣지 않는다.

`ui/test/help.test.cjs`가 메뉴 7개 · 배지 종류 전종 · 관리 명령 전종 · 범위 옵션 3종에 항목이 있는지와,
참조한 문서 앵커가 실제로 존재하는지를 검사한다.

## 문제가 생겼을 때

실패 상태의 원인·복구 안내는 [GUIDE §20](GUIDE.md#20-문제가-생겼을-때--실패-클래스별-복구)의 표를
**단일 출처**로 삼는다. `public/guidance.mjs`는 거기서 파생한 UI 표현이고, 코어의 `last_error` ·
`error_class` · skip 사유 · 상태 줄을 실패 클래스로 옮긴 뒤 클래스마다
**원인 · 영향 · 다음 행동 · 액션 · 무시 가능 여부**를 보여준다(0.6.1 #23).

- 개요의 "확인이 필요한 상태" 카드는 파이프라인 상태를 클래스별로 묶는다. 수집되지 않은 값은 0으로
  세지 않고, 0인 클래스는 카드를 만들지 않는다.
- 활동·추적의 처리 작업 · 모델 시도 · 관리 실행 표에는 **다음 행동** 열이 있고, 지식 변경 · 컨텍스트
  제공 · 시스템 로그에는 같은 내용의 패널이 붙는다. 진행 중이거나 정상 완료한 기록에는 아무것도
  덧붙이지 않는다.
- 액션은 세 가지뿐이다: 기존 관리 명령 allowlist를 그대로 쓰는 **실행 버튼**, 터미널에 붙여넣는
  **복사 가능한 명령**(작업 ID·사유처럼 자유 입력이 필요한 명령은 항상 이쪽이다 — allowlist는
  고정 argv만 실행한다), 그리고 해당 화면으로 가는 **링크**.
- 매핑되지 않은 오류는 **원인을 지어내지 않는다.** 원문을 그대로 보여주고 진단 내보내기로 안내한다.

`ui/test/guidance.test.cjs`가 `src/`에서 `throw new *Error("…")` 문자열과 skip 사유·terminal 상태
enum을 직접 추출해, 각각이 카탈로그에 매핑되거나 테스트 안의 대장에 "매핑하지 않음"으로 올라 있는지
검사한다. 코어에 새 오류가 들어오면 이 테스트가 먼저 실패한다.

## 실행

```bash
npm run build
MEMEX_PLUGIN_ROOT="$PWD" node ui/server.cjs
```

`http://127.0.0.1:3847`. `PORT`로 포트 변경. 별도 프런트엔드 빌드는 없다. 사용자 홈/DB 환경 변수는 기존 값을 상속한다.

`MEMEX_HOME`이 없고 `MEMEX_DB_PATH`만 있으면 home을 그 DB 경로에서 유도하고, 감사 로그(`logs/ui-audit.jsonl`)와 관리 실행 메타데이터(`ui/operations.json`)를 그 home 아래에 쓴다. 정확한 우선순위는 [`ui/README.md`](../ui/README.md)에 있다.

## 계약

조회: `dist/db.js`의 `openReadDb`만 사용. 의미 수정·비활성화·복원·영구 삭제와 계층 승격·강등은 `dist/fact-management.js`를 호출. 모델/임베딩 런타임 미준비 오류를 숨기지 않는다. 기존 core API를 우회하는 raw SQL 수정은 하지 않는다.

Chronicle의 사건 발생/기록 시각을 구분하고 직접 근거와 해석 맥락을 분리한다. 연결 ID가 없는 기록을 추정 연결하지 않으며 후보 탈락 사유·토큰 미수집을 만들어내지 않는다. 그래프 위치는 임베딩 거리 수치가 아니다. 컨텍스트 제공은 답변에서 실제 사용됐다는 증거가 아니다.

관리 명령은 `doctor`, `status`, `sync`, `backfill extract|ontology|embeddings|all`, `recover --all-dead`, `facts migrate-tiers --dry-run|--apply`만 실행한다. `memex backfill receipts`와 `memex ontology merge|rename`은 allowlist에 없다 — 인자를 받는 명령이라 CLI 전용이다. argv는 항상 고정이다 — 작업 ID나 사유를 받는 명령은 버튼이 아니라 복사 가능한 명령으로 안내한다. 모두 전체 저장소 범위로 확인을 요구한다. 상단 필터가 CLI 실행 범위를 제한하지 않는다. 취소는 완료된 데이터 변경을 롤백하지 않는다.

SSE는 조회 갱신 알림이다. 로그/추적 원장 전체 재생 프로토콜이 아니다. UI 연결 상태는 플러그인 전체 건강 상태와 다르다. 실행 출력은 메모리 제한 보관, 실행 메타데이터만 로컬 JSON에 보존한다.

## 지식 지도

`/graph`는 fact 노드와 typed relation(`SUPPORTS`, `INFLUENCES`, `SUPERSEDES`,
`CONTRADICTS`)을 브라우저 네이티브 WebGL로 그린다. `2D Map`과 `3D Galaxy` 모드를
같은 데이터로 전환하며, WebGL을 얻지 못하면 Canvas2D로 자동 대체하고 화면에 실제
렌더러를 표시한다. 서드파티 3D 라이브러리, CDN, 외부 폰트를 쓰지 않는다.

레이아웃은 도메인 그룹만 인코딩한다. **노드 사이의 화면 거리는 임베딩 유사도 수치가
아니다.** 도메인·관계 유형·최대 노드 수(기본 1,200, 최대 5,000)로 필터하며 관계는
30,000개에서 잘린다. 잘린 경우 화면에 그 사실을 표시한다.

ontology와 relation은 protocol v5의 local-derived state다. sync 직후 taxonomy
backfill이 끝나기 전에는 durable fact가 있어도 지도가 부분적으로 비어 있을 수 있고,
privacy purge 뒤에는 재분류 때문에 다시 대기로 보일 수 있다. 이는 오류가 아니다.
빈 결과와 오류는 같은 빈 화면으로 합치지 않는다.

## 점검 항목

1. 빈 DB에서 모든 화면이 오류 없이 열리고, DB 부재를 실제 부재로 표시한다.
2. 대화 → 기억 → 직접 근거와 해석 맥락이 분리된 채로 연결된다.
3. 공통 기억 / 프로젝트 / 전체 범위가 조회·상세·검색에서 동일하게 적용된다.
4. 관계 필터, 노드 선택, 상세 이동, 지도 PNG 내보내기가 동작한다.
5. 사용자 텍스트가 markup이나 script로 실행되지 않는다.
6. 잘못된 method·Origin·Content-Type·본문 크기·CSRF 토큰의 변경 요청이 거부된다.
7. 수정 → 비활성화 → 복원이 `dist/fact-management.js`를 통해 완료된다.
8. 종료 뒤 UI가 만든 서버·리스너·임시 파일이 남지 않는다.

## 로컬 보안

127.0.0.1 바인딩, Host/Origin 검증, 쓰기 CSRF, 경로 제한, escaped rendering/CSP를 적용한다. 인증·TLS·다중 사용자 격리 서비스가 아니므로 포트 포워딩/공개 배포를 하지 않는다. 로그 redaction은 best-effort다.

## API / 테스트

새 UI의 API namespace는 `/api/v2/`. `/bootstrap`에서 CSRF 토큰·코어 정보·스키마 가용성을 조회한다. DB가 없을 때는 실제 부재 상태를 표시한다. 없음/빈 결과/오류를 구분한다. 일부 기존 URL 별칭만 유지하므로 외부 비공개 API 소비자의 전체 호환은 별도 점검한다.

`node --test ui/test/*.test.cjs`로 fixture/HTTP/서비스 호출 계약을 점검한다. 실제 embedding/core 트랜잭션과 브라우저 GPU는 별도로 종단 검증해야 한다.
